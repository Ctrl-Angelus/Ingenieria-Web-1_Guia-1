Backend con Java y Spring-boot

¿Qué es el Backend?

Es la parte de una aplicación que se ejecuta en el servidor. Recibe peticiones del cliente (navegador, app móvil), aplica la lógica de negocio, accede a la base de datos y devuelve una respuesta.

Java en el Backend

Java es un lenguaje tipado, orientado a objetos y multiplataforma gracias a la JVM (Java Virtual Machine). Se usa mucho en el backend por su estabilidad, su ecosistema y su rendimiento. Spring Boot requiere Java 17 o superior en sus versiones actuales.

¿Qué es Spring-Boot?

Principalmente, Spring Framework es un framework que facilita construir aplicaciones Java. Su núcleo es la inversión de control y la inyección de dependencias, mientras que Spring Boot es capa sobre Spring que elimina gran parte de la configuración manual. Ofrece autoconfiguración, un servidor embebido (Tomcat) y dependencias agrupadas en “starters”.

Conceptos

Inversión de control (IoC)
el framework crea y gestiona los objetos en lugar de que lo haga el desarrollador con new
Inyección de dependencias (DI)
el framework entrega a una clase los objetos que necesita.
Bean
es un objeto gestionado por el contenedor de Spring.
Starter
dependencia que agrupa todo lo necesario para una funcionalidad (por ejemplo, spring-boot-starter-web).
Maven/Gradle
herramientas que gestionan dependencias y la construcción del proyecto.
API REST
estilo de arquitectura para comunicar sistemas usando HTTP.

Arquitectura en capas

Permite dividir una aplicación en diferentes secciones que tienen diferentes responsabilidades y que se pueden intercambiar y modificar sin afectar a las demás capas.

En primer lugar, está el Controlador, que se encarga de recibir las peticiones HTTP del cliente y envía las respuestas. El Servicio contiene toda la lógica de negocio de la aplicación, incluyendo la verificación de permisos. El Repositorio se encarga de acceder a la base de datos. El Modelo/Entidad es la representación de los datos que se almacenan en la base de datos. Es utilizado por todas las otras capas.

Anotaciones básicas

Tabla de anotaciones principales de Spring-Boot
Anotación Función
@SpringBootApplication Punto de entrada de la aplicación; activa la autoconfiguración.
@RestController Clase que atiende peticiones HTTP y responde en JSON.
@RequestMapping Define la ruta base del controlador.
@GetMapping, @PostMapping, @PutMapping, @DeleteMapping Asocian un método HTTP con un método Java.
@PathVariable Lee un valor que viene en la URL.
@RequestBody Convierte el JSON de la petición en un objeto Java.
@Service Marca una clase que contiene la lógica de negocio.
@Repository Marca una clase de acceso a datos.
@Autowired Solicita una dependencia; hoy se prefiere la inyección por constructor.
@Entity Marca una clase como tabla de la base de datos.

Ejemplo


@SpringBootApplication
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
                

@RestController
@RequestMapping("/api/saludo")
public class SaludoController {

    @GetMapping
    public String saludar() {
        return "Saludo desde Spring Boot";
    }

    @GetMapping("/{nombre}")
    public String saludarA(@PathVariable String nombre) {
        return "Hola, " + nombre;
    }
}

¿Cómo se crea un proyecto de Spring-Boot?

Primero, hay que entrar a la herramienta Spring Initializr. Elegir Maven o Gradle para gestionar el proyecto, Java y la versión de Spring-Boot. Agregar dependencias: Spring Web, Spring Data JPA, un driver de base de datos (H2, MySQL o PostgreSQL).

El proyecto se descarga en un .zip que hay que descomprimir, el cual se puede importar en algun IDE. Para ejecutar el proyecto se debe ejecutar la clase principal en el IDE o con el comando mvn spring-boot:run para Maven, gradle bootRun. Si no se tiene Maven o Gradle instalado, se puede hacer lo mismo con los wrappers de cada uno (archivos ejecutables en la raiz del proyecto, mvnw/gradlew).
